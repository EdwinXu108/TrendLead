## 必须修复

**1. 行情下载被限频，却被记成了“没有数据”。**
`stage2_price_gaps.csv` 中有 394 只证券的原因是“获取历史K线频率太高，请求失败，每30秒最多60次”。这是请求失败，不是没有数据。额度并不紧张（剩余 838）。要求：
- 下载时主动限速，每 30 秒不超过 50 次请求；
- 遇到限频错误，等待后重试（最多 3 次）；
- 缺口原因分成“请求失败（可重试）”“接口返回无数据”“身份未映射”“未知股票或证券 ID 为 0”等类别，不能混成一类“missing”；
- 重跑下载，直到只剩下确实取不到的证券。

**2. 行情区间太短。**
现在只有 2025-06-01 至 2026-03-31（209 个 session），无法支持第三、四阶段（最长窗口 126 日，还要划分开发段和保留段）。改为：价格从 **2019-05-01** 开始（第一份名单 2019-11-28 公开，前面留出至少 126 个 session 的预热期），到可取得的最近交易日为止。先统计需要下载的去重证券数，再与剩余额度比较：够用就全部下载；不够就停下，报告缺多少，等投资者决定。不能只下载一部分股票。

**3. 证券身份不能用“名称前缀”匹配。**
`stage2_identity_issues.csv` 中 28 条 `ticker_mapped_via_prefix` 里，有多条映射到了错误的证券，例如：
- 西方石油普通股（CUSIP 674599105）→ `OXY-WT`（权证）
- 富国银行 → `WFC-PZ`、Citizens Financial → `CFG-PI`、Zions → `ZIONP`、Huntington → `HBANP`、Charter → `CHTRP`（都是优先股）
- Molson Coors → `TAP-A`（基金实际持有的是另一个股票类别）

这些品种恰好是投资者明确排除的。要求：
- 删除按名称前缀匹配的逻辑；
- 按 CUSIP 映射，使用免费、可追溯的来源（例如 OpenFIGI 的 CUSIP 查询，限定美国交易所的普通股；或 SEC 公司代码对照表加 CIK 核对；N-PORT 申报中的 ISIN、LEI 可作交叉证据）；
- 映射结果的证券类型如果是权证、优先股、单位、债券等，一律拒绝，进入身份问题表；
- 每条映射记录方法和证据。映射不上的证券不要猜。
- 在报告中单独统计：**在所选区间内实际出现在名单中的成员**，有多少已经映射、多少未映射。

**4. 公司行动必须取得：现在事件数为 0。**
交接说明称“本机 futu 没有公司行动接口”，这与项目里已有的核查结果矛盾。`work/opend_data_audit.py` 在本机成功调用过 `get_rehab(code)` 和 `get_corporate_actions_dividends(code)`，结果记录在 `work/opend_audit_2026-10-24/findings.json`（AAPL、COST、WDC 都取得了除息日和派息日）。请参照那份脚本：
- 为每只证券取得拆合股和现金分红，规范化为 events：拆合股写成 `shares_new_per_old`，并用除权日前后的不复权价格核对比例；分红写明除息日、派息日、每股金额；
- VOO 的分红也要取得，基准需要；
- 没有公司行动，评分用的总回报和账本都会出错：拆股日的不复权价格会突然大跌。据我所知，这个区间内有大比例拆股的成员，例如 O'Reilly（2025 年 6 月，1 拆 15）和 Netflix（2025 年 11 月，1 拆 10），请用数据核实；
- 增加一项自动核对：任何一只证券，如果某天不复权收盘价相对前一天的变化超过 ±40%，而当天没有对应的拆合股事件，列入 `stage2_corporate_action_gaps.csv` 待查；
- 如果个别证券确实取不到公司行动，可以用“不复权价格与前复权价格之比的跳变”推断拆股，但必须标为推断，并单独列出。

**5. 行业不能全部是 UNKNOWN。**
全部为 `UNKNOWN:<issuer>` 时，行业数量上限完全失效，等于没有分散约束。请：
- 先复用已有证据：`work/universe_verification_2026-10-24/exchange_candidate_industry_memberships.csv` 和 `industry_members/`（富途 145 个行业的成员名单，2026-10-24 取得）；
- 覆盖不到的成员，逐只查询富途所属行业，遵守限速，漏返回的重查一次；
- 记录来源和取得日期，标注“当前分类，非历史分类”；
- 报告行业覆盖率；只有重查后仍查不到的，才记为 UNKNOWN。

**6. REIT 必须确定，不能停在待核。**
`stage2_reit_review.csv` 有 17 条待核，而标普 500 中通常有约 30 只 REIT。请对名单中全部成员系统核对：用 SEC 申报主体资料中的 SIC 代码（6798 = REIT，可以从 SEC 的 submissions JSON 按 CIK 取得），结合行业名称，输出最终的 REIT 名单及证据，并在资格判断中排除。确实无法判断的列出来，并报告数量。

**7. 交易日历要有提前收盘。**
现在的日历来自 VOO 的交易日，所有 session 都按正常时间收盘。请根据 NYSE 官方公布的休市和提前收盘安排（例如独立日前一天、感恩节次日、平安夜的 13:00 收盘），为 2019–2026 年建立本地文件，注明来源 URL 和核对日期，并与 VOO 的交易日交叉核对。

**8. 名单公开时间取错了。**
现在 `available_at` 取自 SEC submissions JSON 的 `acceptanceDateTime`。经 Claude 核对，这个字段与申报索引页上的“Accepted”时间不一致：例如 accession `0000036405-26-000063`，索引页显示 Accepted 为 `2026-02-26 16:15:30`（美东时间，即 21:15:30 UTC），而当前数据记为 `2026-02-27T02:15:30Z`，晚了 5 个小时。方向虽然偏保守，没有提前使用信息，但数值是错的，可能让名单晚一周才被使用。请：
- 改用申报索引页或申报头文件中的受理时间（美东时间），按 `America/New_York` 转换为 UTC；
- 28 份名单全部重新取值，并列出与旧值的差异；
- 增加测试：用保存的索引页样本解析受理时间。

**9. `validate` 要检查覆盖率，不能在大量缺数据时报告 ok。**
现在 75% 的成员没有价格，`validate` 仍然报告 `blocking_issues=0`。请在 `validate` 中，按每个信号周统计：最新可用名单中的合格成员数（排除 REIT、选定股票类别之后）、其中有有效评分的数量和比例、无法评分的原因分布。增加一个事先登记的工程门槛（建议：有效评分比例低于 95% 的信号周标为“数据不足”），把达不到门槛的周列出来。在报告中给出满足门槛的最长连续区间。门槛值写入 `config/v05_stage2.json`，并注明“工程门槛，未经验证”。

**10. 计数要能对上。**
交接说明写名单中有 669 个去重 CUSIP，但 `stage2_price_gaps.csv` 有 937 只不同的证券。请统一以 `security_id` 计数，说明这些数字的来源，确保覆盖报告中的各项计数可以相互核对。

**11. 实验登记重做。**
现有的 `stage2_experiment_registry.json` 建立在上述有缺陷的数据之上，作废：保留原文件并在其中注明作废原因，然后在数据修复后，按满足覆盖门槛的连续区间重新生成。仍然要在查看任何真实收益之前写定。
