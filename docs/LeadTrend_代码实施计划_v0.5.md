# LeadTrend 代码实施计划 v0.5

日期：2026-10-25  
实现：Xiaomi MiMo v2.6  
审阅：GPT 与 Claude；投资者安排每一阶段的实现任务。

以 `docs/LeadTrend_研究方案_v0.5.md` 和根目录最新 `AGENTS.md` 为依据。本文件提供交付顺序，不把未验证参数变成收益结论。当前轮次只编写文档，没有授权 GPT 或 Claude 自行修改正式代码。

## 1. 实施原则

第一阶段交付能运行的完整小闭环，不把“建一个数据平台”作为第一个交付物。随后接入真实数据、扩展必要事件、比较参数。四个阶段之外的增强研究暂不实施。

不要求阶段一同时证明盈利、拿全历史或处理所有公司行动。必须区分“不支持”和“结果是零”，禁止用忽略异常来伪造闭环。

只使用免费数据和依赖。本地现有核查环境：`D:\Tools\miniconda3\python.exe`，Python 3.13.12、pandas 3.0.6、numpy 2.5.3、pytest 9.1.1；交易日历包当前未安装。它们是本机观察，不是要求其他环境必须使用完全相同版本。

## 2. 与旧原型隔离

现有 `leadtrend/`、`tests/`、`config/research_registry.json`、`pyproject.toml`、旧 README 是此前未获认可的原型，不能视为 v0.5 已实现的基础，更不能默认沿用其全市场市值筛选。

建议新增以下轻量目录，不改动或删除旧原型：

| 位置 | 用途 |
|---|---|
| `leadtrend_v05/` | v0.5 Python 包，`python -m leadtrend_v05` 入口 |
| `tests_v05/` | 只覆盖当前阶段的独立测试 |
| `config/v05_bootstrap.json` | 未验证工程基准；所有数值有明确名称 |
| `data/v05/fixtures/` | 明确标记 synthetic 的可复现小数据 |
| `data/v05/raw/` | 阶段二以后取得的真实原件，只追加保存 |
| `data/v05/normalized/` | 规范化输入，与原件可追溯 |
| `work/v05/` | 运行结果、核查报告和临时文件 |
| `docs/README_v0.5.md` | v0.5 专用命令和当前支持范围（文档统一放在 `docs/`） |

不做 Web 界面、数据库服务、自动调度、消息推送或实盘接口。输出先用 CSV、JSON 和 Markdown；CLI 能重现结果即可。

## 3. 阶段一：离线小闭环

### 目标

用明确标记的模拟数据，实际跑完：已公开名单选择 → 身份/类别处理 → 单窗口评分 → 行业约束和保留缓冲 → 下一交易日模拟成交 → 拆合股/普通分红 → 账户和 VOO 基准 → 文件报告。

这是工程流程验证，不是 VOO 历史收益研究。第一阶段不联网、不调用 OpenD、不导入交易 SDK。

### 必须实现

- 定义下文最小数据契约，读取本地 CSV/JSON，验证时间、主键、价格和来源。
- 名单选择遵守 `available_at`，包含持仓所属日期、公开日期不同，以及修订晚于信号日的案例。
- 稳定证券/发行人映射，执行明确证券排除；没有市值、成交额资格门槛。
- 类别选择先于趋势评分，同一输入不随趋势窗口或持仓数偷偷改类别。
- 一种单窗口总回报评分，工程配置 L=20、N=10、k=3、b=2。
- 实现正常可交易路径的可行顺序、保留线、行业校正、总数校正和补位。
- 明确的 session 日历输入：每周最后交易日收盘产生信号、下一 session 开盘模拟成交；测试包含周五休市和提前收盘，不依赖“周一到周五就是交易日”。
- 整股、每笔 1 美元、不利滑点、先卖后买、非负现金、净股数差交易；只在有换股（退出或补位）的周恢复接近等权，无换股的周不下任何单。
- 拆合股和普通现金分红：评分收益与实际到账分开，不重复计权益。拆合股恰好在执行 session 生效时，先换算持仓股数和参考价格，再计算目标股数；分红归属以除息日前一 session 收盘时的持股为准（除息日开盘卖出仍享有，除息日开盘买入不享有）。
- VOO 仅作为独立基准曲线，不能进入策略订单或策略持仓。
- 生成可核查的每周名单/评分/决策、成交、每日资产、基准、配置和汇总。

### 模拟数据要求

小数据包含至少 24 个虚构股票、至少 4 个行业、两个不同公开时间的持仓快照、至少约 90 个 session；可在小范围中构造若干独立场景，不要求一个夹具同时承载所有异常。

至少一组夹具必须能真正测试保留缓冲：在 N=10、k=3、b=2 下，可行次序 F 的长度要大于 20（至少 7 个行业、每个行业至少 3 只合格股票，建议 8 个以上行业、40 只以上股票），否则保留线总是落在 F 最后一位，缓冲逻辑没有被测试。也可以在单元测试中用更小的 N、k 构造同样条件。

模拟基准使用 `VOO` 标识但明确 `dataset_kind=synthetic`，不冒充真实价格或真实持仓。模拟证券可用 `SYN_...` 标识。至少覆盖成员新增/移除、同发行人双类别、一个被明确排除品种、拆股、除息与晚到现金、名单未来污染。

### 边界

本阶段不实现历史持仓下载器、批量 OpenD 行情获取、全参数搜索、同伴加分、相关性/PCA、完整停牌/退市/分拆/并购账本。遇到实际输入包含未支持事件，要输出带事件和证券 ID 的未支持报告并失败，不能忽略后给出成功净值。

### 交付与验收

- 专用包、测试、工程配置、模拟输入及生成/说明文件、`docs/README_v0.5.md`。
- 一条离线命令产生完整 demo，一条命令运行 `tests_v05`；不得调用旧测试集来代替新验收。
- `work/v05/stage1_demo/` 有 `run_manifest.json`、`universe.csv`、`scores.csv`、`decisions.csv`、`trades.csv`、`daily_equity.csv`、`benchmark.csv`、`summary.json`、`data_issues.csv`。
- `work/v05/stage1_review.md` 写实际命令、退出状态、已支持/未支持项、配置和文件清单；不写“策略已盈利”。
- 同样输入重复运行，除运行时间等元数据之外产生相同经济结果；名单函数二次应用不发生空转换仓。不要把名单幂等夸大成完整资金模型已经证明正确。

完成后停止。将文件与命令交给 GPT、Claude 审阅，不自行开始阶段二。

## 4. 阶段二：接入真实 VOO 名单与行情

### 目标

用真实来源替换模拟输入，不改变已经通过审阅的基础规则。先取得足够验证流程的连续区间，不先追求全部年份。

### 工作内容

1. 建立官方持仓原件清单与解析器，校验基金 Series/Class，不能解析成整个 Vanguard 集团持仓。
2. 至少解析两份不同所属日/公开日的真实名单，并针对一份晚公开名单复现“公开前不可用、公开后才更新”的效果。能取得更多连续快照则直接扩充，不把两份样本说成全历史已齐。
3. 保存报告日、受理/公开时间、版本、原件、SHA256、证券标识及未分类行。不能用 `retrieved_at` 代替 `available_at`。
4. 取得该连续区间内曾经出现在名单中的证券，以及所需预热期的原始日行情和公司行动；旧成员、改名证券、后来退市证券都列入需求清单，不只下载最新名单。
5. OpenD 或其他免费来源只使用行情接口。先读本地缓存，再按去重缺口请求；记录请求数量、历史额度变化、失败原因和取得时间，缓存可断点恢复。不得一次盲目请求全部全市场证券。
6. 使用可追溯的真实 NYSE session 日历。免费日历依赖或经官方核对的本地文件均可，必须记录版本。
7. 补充实际入池证券的类别和主行业映射。旧全市场核查资料只作证据，不把原来的 865 主体名单作为入池条件。
8. 输出 `coverage_report.json`、`holdings_manifest.csv`、`identity_issues.csv`、`price_gaps.csv`、`corporate_action_gaps.csv`，明确能运行的连续区间和缺口。

SEC 访问遵守官方公开访问要求，使用透明的正常请求方式并缓存、限速；403/429 不无限重试，不伪造认证或调用用户交易账户。

### 验收

- 实际文件中能追到 VOO：Series `S000002839`、ETF Class `C000092055`；逐份核对，不假定所有历史文件都由同一 CIK 提交。
- 手工抽查原件中的证券、所属日、公开时间和解析结果一致。
- 数据质量报告区分“未发生交易”“没有报价”“源接口无效记录”“身份不确定”；不能统一填 0。
- 所有候选下载失败都有记录，不把失败证券悄悄移出历史名单。
- 本阶段不选优参数、不发表收益胜负。先确定实际样本日期与分段，再保存后续实验登记。

数据覆盖不足允许先跑明确标记的近似实验；如果已持有资产无法估值或处置，必须暂停该条运行并保存最后可解释状态。不得靠删掉资产让结果继续。

## 5. 阶段三：真实基础版本与必要事件

### 目标

用真实数据跑工程基准，优先验证账本和执行，只查看事先登记的开发段，不借此提前筛保留段参数。

### 工作内容

- 接通阶段二输入，移除 demo 对真实流程的临时假设，保持评分/名单/执行模块共用。
- 实现可交易、冻结、应收现金、应收证券分项账本；资金不因减值、公告或冻结估值变化凭空释放。
- 按研究方案处理冻结占位、行业剩余容量、N 减小和被动超限；不再用“只停买”冒充持仓上限。
- 支持真实区间实际遇到且有可靠权益数据的分拆、收购和证券转换；优先处理遇到的事件，不预先写一个包罗全部市场事件的大框架。
- 对缺乏可靠权益或价格的事件，保留未解决状态，报告受影响日期，不伪造回收率或把退市统一折价。
- 在日账本上核对权益守恒和交易资金；每个费用、分红、转换事件有唯一 ID，重放不重复入账。
- 输出完整基准运行和限制说明，展示少量代表周的“为什么买卖”表供人工核对。

### 验收

必查：拆股本身不创造损益；分红不重复；收购公告不等于现金到账；冻结证券不能卖出；分拆证券不能被隐藏；名额扣除冻结后再补位；不能负现金；真实价格与评分指数不串用；VOO 比较区间对齐。

账本资产恒等式：可用现金 + 股票价值 + 应收现金 + 应收证券及其他受限资产价值 = 账户总权益。行情涨跌和真实权益事件会改变权益，普通科目转移不会创造资金。

当前覆盖不足时，可以交付“真实数据近似实验”；报告名称必须如此标记。不能因为程序跑完就宣布数据无偏或策略有效。

## 6. 阶段四：有限参数比较与研究报告

### 目标

回答基础策略是否有继续研究价值，不以挑到最高收益参数作为成功标准。

### 工作内容

- 使用研究方案的 36 个核心候选点；必须在查看相应真实收益之前登记。未登记的尝试另记，不隐瞒总尝试次数。
- 在相同数据版本、类别选择和成本假设下比较，基础滑点与双倍滑点都报告。
- 先检查开发段的结果与邻近参数，冻结评价口径，再运行预先留出的时间段；保留段不再反复调参。
- 对 VOO 报告总回报、相对净值、回撤、换手、交易笔数、持有时长、行业暴露、最大几只股票的收益贡献。
- 记录价格/身份/公司行动缺口与持仓是否有关，不能假定共用数据就使偏差抵消。
- 交付可复现的运行清单、全参数结果表、参数邻域图和分时期表；不用一个“最优参数”结论遮盖其他结果。

此时再决定是否值得进入同伴支持、集中度诊断或前瞻影子运行，不自动将它们接到基础策略中。

## 7. 最小数据契约

下列为字段含义约束，可按实际代码拆表；不要求建立复杂数据库。

| 数据 | 最小字段与要求 |
|---|---|
| 运行配置 | `dataset_kind`、L、N、k/派生方式、b、100000 本金、1 美元费用、滑点、起止范围、时区约定 |
| 名单表头 | `snapshot_id`、`holdings_as_of`、`available_at`、`availability_precision`、`source`、`retrieved_at`、原件哈希 |
| 名单明细 | `snapshot_id`、`security_id`、原始名称/标识；权重可选，不用于评分 |
| 身份/行业 | 稳定 `security_id`、`issuer_id`、ticker 有效期、证券形式、行业、来源与版本；行业如为当前分类须标明 |
| 原始行情 | `security_id`、session 日期、未复权 open/close，必要时 OHLC、volume/turnover；记录货币和来源；同键不能重复冲突 |
| 公司行动 | 唯一事件 ID、证券、事件类型、生效 session、明确的股数转换、现金金额及口径、实际付款/交付日、来源 |
| 交易日历 | session 日期、带时区的开盘和收盘时间；明确提前收盘/休市 |
| 账户状态 | 股数、可用现金、应收权益、冻结原因、估值时间/方法；不使用单一“总权益减冻结”代替全部科目 |
| 运行产物 | 运行 ID、输入/配置哈希、代码版本标识、数据种类、每周依据、交易、日权益、基准、缺口、摘要 |

仅有公告日期的字段，不能替代公司行动生效日期。模拟数据的来源和公开时间也必须显式给出，不能让测试默认所有快照一开始都可见。

## 8. 审阅方式与分工

MiMo 每阶段交付文件清单、实际运行命令、输出、已知缺口和阶段边界说明。GPT、Claude 均可审阅代码和产物，但不得假称另一方已经通过审阅。投资者指定审阅优先级：Claude 高于 GPT，review 和文档修改优先由 Claude 进行，两者意见冲突时以 Claude 为准。

建议分工：

- GPT 重点检查时间可得性、数据来源、选择逻辑、工程可复现性及与 v0.5 的一致性。
- Claude 重点检查账户、公司行动、冻结和名额、费用、基准及实验公平性。
- 两方都要能指出具体文件、输入、预期和实际结果；不能只说“有前视风险”而没有可定位证据。

审阅分级：

1. **必须修复**：未来信息进入名单或评分、遗漏/删除资产、收益重复计算、负现金、违反明确投资边界、无法复现。
2. **明确标注可先运行**：当前行业分类、已记录的数据覆盖限制、未验证工程默认值、模型化的成交和结算假设。
3. **后续建议**：同伴支持、相关性、额外参数、界面和性能优化。不得自动作为阶段一阻塞条件。

修复后的阶段只回归受影响检查与必要核心测试，不为低影响修改反复重跑全部研究。单元测试通过不等于真实数据已验证，真实历史曲线好看也不能替代资金与时间逻辑检查。

## 9. 每阶段结束时的交接模板

提交：阶段编号；本次新增/修改路径；实际测试与 demo 命令和退出码；可打开的输出路径；支持范围；未支持/未解决项；违反或偏离规格之处；需要审阅者定位的具体问题。

不得自动进入下一阶段、接入实盘交易、扩大研究股票池，或声称已经得到“最佳策略”。后续阶段由投资者安排相应实现任务。
