# LeadTrend 回测引擎 bt_v1

`leadtrend_bt/` 只通过 `leadtrend_db/api.py` 读取数据库，不导入、不修改 `leadtrend_v05`。测试在 `tests_bt/`。

## 规则

1. **信号日：**每周最后一个交易日（`friday_signal_days`）收盘后。在该日生效的股票池（`pool_at`）中，只对过去至少 L+1 个交易日都有总回报数据的证券评分。
2. **分数：**动量 = `tri_t ÷ tri_{t−L} − 1`。从高到低排名，同分按 `security_id` 排序。
3. **选股（保留缓冲 b）：**已持有且仍在池中、排名 ≤ b × N 的继续持有；不在池中或排名 > b × N 的卖出；空出的名额按排名补足到 N 只；同一公司的多个类别只取排名最高的一个。
4. **成交：**下一交易日开盘价；买入 = 开盘 × (1 + 滑点)，卖出 = 开盘 × (1 − 滑点)；每笔订单 1 美元；整股；现金不能为负；先卖后买。R2：保留的股票不调整仓位，卖出所得加现有现金在新买入之间等分；首次建仓等分 N 份。当日没有开盘价（停牌/缺日）的订单顺延到该证券下一个有开盘价的交易日。
5. **公司行动：**拆股/合股调整股数；现金分红在除权日计入现金；分拆在除权日按 `spin_value`（缺失时用复权因子隐含价值，再缺失时用除权日开盘缺口）折成现金。与 `tri_daily` 的 `event_v1` 完全同源。
6. **分批 K：**资金等分 K 份；子账户 j 在第 j 个信号周建仓，之后每 K 周检查一次；独立成交、独立计费；合并账户为各子账户之和。
7. **现金收益 0。**
8. **基准：**VOO 按总回报单位持有，起点为策略第一笔成交当日的开盘价（`units = 本金 ÷ (tri × open/close)`）。
9. **区间：**默认 2014-02-28 至 2024-06-28。`end > 2024-06-28` 抛 `HoldoutError`（保留段保护）。

## 配置项

`run_id, mode, start, end, L, N, b, K, cost_bps, fee_per_order, capital, seed, plan`

`mode`：`momentum`（默认）、`random`（随机对照，用 `plan` 给出每个信号日的新买/卖出名额）、`pool_ew`、`pool_cw`、`top10_cw`（按基金持仓金额的权重组合，每次版本变更全额换手，允许小数股）、`voo`（买入持有基准）。

## 输出（`work/bt_runs/<run_id>/`）

| 文件 | 内容 |
|---|---|
| `config.json` | 本次配置 |
| `daily_equity.csv` | 日期、现金、持仓市值、总权益、VOO 基准值 |
| `trades.csv` | 日期、子账户、证券、方向、股数、成交价、费用、原因、信号日 |
| `positions.csv` | 每日每子账户持仓 |
| `weekly_decisions.csv` | 每个信号日的入选、保留、卖出、排名、分数 |
| `summary.json` | 全部指标 |

## 指标

CAGR（按 252 个交易日年化）、相对 VOO 的年化超额、年化波动、夏普（(CAGR − 区间平均 DTB3) ÷ 波动）、β、跟踪误差、最大回撤及峰值/谷底/恢复日、最长水下交易日数、逐年收益与超额、最差自然年、两个时段（A：2014-02-28 至 2019-11-29；B：2019-11-29 至 2024-06-28）的 CAGR 与超额、年单边换手、平均持仓数、最大单股权重、平均仓位、前 5 大盈亏发行人及其占比。VOO 的同样数字一并输出。

## 验证（`tests_bt/`）

| 项 | 内容 |
|---|---|
| 合成数据 | 3–5 只证券、20 个交易日；手算成交价、手续费、整股取整、R2 现金分配、保留缓冲、拆股、分红、分拆、分批的建仓与检查日 |
| 不变量 | 每日总权益 = 现金 + Σ 股数 × 收盘价（1e-9）；现金不为负；同一信号日不买卖同一证券 |
| 基准一致 | 买入持有 VOO 的比值等于 tri 的比值（相对误差 1e-12） |
| 向量化对照 | 零成本、小数股、等权持有全池，与独立计算的权重漂移组合逐日一致（相对误差 1e-9） |
| 可重复 | 同一配置运行两次，输出文件逐字节相同（`tests_bt/test_repeatable.py`） |
| 保留段 | 结束日晚于 2024-06-28 报错 |
